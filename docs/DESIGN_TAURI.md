## 1. 前提

### 1.1 利用者と仕事

利用者は技術者です。画面の仕事は次の 3 つに限ります。

| # | 仕事 | 画面 |
| --- | --- | --- |
| a | 実機の現在値を確認する | 接続 / 現在値 |
| b | 設定・リマップ・マクロを編集する | 設定 / リマップ / マクロ |
| c | 書き込む前に安全を確認する | 右レールの「書き込み前の確認」と確認ダイアログ |

「きれいに見せる」は仕事ではありません。**数値が信用できること**、**今どこにいるか分かること**、**書き込む前に何が変わるか分かること**の 3 つが満たされていれば十分です。Web UI になったことで CSS の自由度は上がりましたが、自由度は装飾ではなく、面・字・余白・状態の精度に使います。

### 1.2 不満 3 点への回答

| 不満 | 原因（前回レビューの結論） | 今回の回答 |
| --- | --- | --- |
| 濃色テーマが平均的 | 面が Fluent 既定の 4 段グレー、アクセントが `#0067C0`、光が 1 色で 5 つの意味を兼ねていた | **明るい作業面を既定にする。** 色は「正常は無彩色、注意は琥珀、異常は赤、選択は青緑」に固定し、発光（LED）は暗い面だけで使う（§5.1） |
| 日本語がおかしい | 実装の言葉（レポート、スナップショット、自動で開始）と翻訳調（コロン、括弧補足）が混在 | 用語集を先に固定し、文体・句点・単位の規則を決める（§6）。「録音」は入力記録に使わない |
| 応答しないことがある | 待ち状態の可視化がなく、無反応と処理中が区別できない | 受理 100 ms / 待機表示 400 ms / 中止提示 2 秒の 3 段階と、すべての無効化に理由を付ける（§5.7.3） |

### 1.3 制約

- ウィンドウ最小 **900×620**。初期 1280×800。200% ズームで破綻しない（TAURI_PLAN.md §9.1）
- 日本語が主、英語に切替可能。技術名（BLE / GATT / MTU / SHA-256）は訳さない
- 同梱フォントは既存の 5 書体を前提にする（Noto Sans JP / NotoEmoji / Ubuntu-Light / Hack / emoji-icon-font）。**新しい書体は追加しない**。ライセンス画面（P6）の対象を増やさないためです
- 入力は BLE の 20 ms 通知を Rust 側で間引いて event に載せる（TAURI_PLAN.md §3.1）。描画は 60fps を目標にする
- アイコンセットは今回導入しない。必要な記号は 16px・1.5 stroke のインライン SVG を最小限だけ自作する

## 2. 前回（egui 版）からの継承と破棄

前回の「燻しスレート — 実機の素材と、ひとつの光」は、素材を製品に寄せる判断としては正しく、トークンもコントラスト実測付きで `theme.rs` に実装されました。今回作り直すのは、**暗色固定という前提そのもの**です。Web UI では面を選び直せるため、暗色を既定にする理由がなくなりました。

### 2.1 継承する

- 「構造はヘアライン、操作は 3:1」の原則（区切り線は 1.3:1 でよいが、押せるものの輪郭は 3:1 以上）
- 数値は等幅・桁揃え、hex は `0x` + 大文字、単位は半角スペース
- 主キーを色で塗らず、面の明度で目立たせる考え方（暗色ではオフホワイト、明色では墨）
- 状態を 1 か所に集約し、同じ意味に同じ色を使う
- コントラストを計算して文書とテストに残す
- リング（輪）を状態の言語にする考え方（今回は「光のステージ」に発展させる）

### 2.2 破棄する

- 暗色の燻しスレート 4 段を既定にすること
- 「光はひとつ」を画面全体に適用すること（明るい面では光が読めない）
- リングを装飾として全画面に置くこと（輪は入力モニターの中だけに残す）
- Medium ウェイトの追加（Web では 400 / 500 / 700 が最初から使える）
- egui 固有の実装（`LayoutJob`、`animate_*`、`Frame` ヘルパ）。同じ意図を CSS で表現する

### 2.3 前回レビューの Must Fix の扱い

前回の Must Fix（ログのレイアウト破綻、空状態の構成、太字 1 種類、色と光の設計）は、egui 版では未適用のまま凍結されます。Tauri 版では**最初から作り直す**ため、同じ破綻を持ち込みません。特に次を設計で固定します。

- 空状態は「状態 + 次にすること 1 つ」を必ず組む（§5.5.9）
- 見出しは 15/500、主役だけ 18〜24/700（太字を階層の唯一の手段にしない）
- 無効化は輪郭を消し、理由を 1 行上に出す（押せると誤読させない）

### 2.4 P0 雛形（`apps/desktop`）との差分

P0 で `apps/desktop` の雛形（React 19 / Vite / Tailwind v4 / vitest）が追加されています。P1 では次の点を本設計へ置き換えます。

| P0 雛形の現状 | P1 の決定 |
| --- | --- |
| 左ナビは デバイス / ライブ入力 / 設定 / マクロ / ログ | 接続 / 現在値 / 設定 / リマップ / マクロ / ログ。入力モニターは右レール（拡大で全画面） |
| `src/index.css` の `@theme` が Inter / JetBrains Mono | 同梱済みの Noto Sans JP / Hack に置き換える。未同梱フォントは追加しない（ライセンス更新を避ける） |
| `@theme` が slate の暗色のみ | ライト面 + ダークステージのトークン（§5.1）に置き換える |
| トークンが `index.css` に直書き | `apps/desktop/src/styles/tokens.css` に分離し、`index.css` から読み込む（予定パス） |
| 空状態はアイコン + 1 文 | 「状態 + 次にすること 1 つ」（§5.5.9）に統一。アイコンは飾りなので置かない |

## 3. 方向性 3 案

3 案は「前回の 3 案をなぞらない」という条件で作り直しました。評価軸は 4 つです。

1. 不満（暗色が平均的）に答えているか
2. 3 つの仕事（読む / 編集する / 確認する）に効くか
3. 8BitDo Ultimate 2 に固有か（他製品の画面に置き換えても成立しないか）
4. 実装コストとリスク（Web UI で破綻しないか）

### 3.1 案 A: 昼の作業台（Daylight bench）

校正台の上で数値を読む画面です。影も光も使わず、罫線・余白・組版だけで構造を作ります。

- **配色**: 背景 `#F6F7F8` / 面 `#FFFFFF` / 沈み面 `#EDEFF1` / 罫線 `#D8DDE1` / 文字 `#1A1D20` / 補助 `#5E6871` / アクセント `#1F5FBF`（青）/ 状態 `#1B7F4B` `#8A5200` `#B02418`
- **タイポグラフィ**: Noto Sans JP（400 / 500 / 700）+ Hack。13/20 を基調、見出し 18/28、注記 11/16
- **余白**: 4px グリッド。行 32、セクション間 32、カード内 20
- **コンポーネント**: 1px 罫線、角丸 6、影なし。主キーは青の塗り、副キーは白 + 罫線
- **長所**: 読みやすい。AA を取りやすい。長時間の編集に強い。実装が最も速い
- **短所**: 「明るい業務ツール」自体が既定解で、色を青にした時点で他社ツールと区別がつかない。入力モニターの光が白地で死ぬ。夜間はまぶしい
- **8BitDo Ultimate 2 に固有か**: **低い。** アクセントを `#0067C0` に戻せば前回の画面に戻る。固有の図形・素材がない

### 3.2 案 B: 刻印と打刻（Silkscreen plate）

実機の印刷ラベルと型番の言語を使う画面です。ラベルは「刻印」、値は「打刻」として、罫線と文字組みで質感を作ります。

- **配色**: 紙 `#F2F1ED` / 濃紙 `#E8E6E0` / 罫線 `#C9C5BB` / 文字 `#1C1B18` / 補助 `#6B675E` / アクセントなし（状態色のみ `#2F5D3A` `#8A5200` `#9A2B1F`）
- **タイポグラフィ**: Noto Sans JP を 400 と 700 の 2 ウェイトだけ。見出しは 15/500 で字間 +0.04em、値は Hack 12。本文 13/22
- **余白**: 4px グリッド。版面は 8px 単位。行 34、セクション間 24（罫線で区切る）
- **コンポーネント**: 角丸 0〜2。窪みは「上 1px 濃 + 下 1px 明」で表現。ボタンは押し出しではなく罫線の枠
- **長所**: 文字が主役で記憶に残る。数値の打刻感が計測器らしい。彩度を捨てるので派手にならない
- **短所**: 窪み表現がフォーム部品（入力・スイッチ）と相性が悪く、Web の標準部品を自作せざるを得ない。状態色が紙の上で浮く。印刷物の見た目は「操作できる」印象を弱める。暗い面と併用できない
- **8BitDo Ultimate 2 に固有か**: **中。** 実機の刻印ラベルには由来するが、その質感は機能と結びついていないため、装飾に落ちやすい

### 3.3 案 C: 昼の作業台と夜のステージ（Bench + stage）— 推奨

読む・書く面は明るい作業台、**見る面（入力モニター）だけ暗いステージ**にします。理由は装飾ではなく事実です。このコントローラの唯一の自己表現は光（リング LED と 24 LED）であり、光は暗い面でしか意味を持ちません。だから画面の明度を「仕事の種類」で分けます。

- **配色**: 明るい面は §5.1 のライトトークン。ステージは `#0E1115` / `#141A1F` に LED `#6FE7D8`。正常は無彩色、注意は琥珀、異常は赤、選択は青緑、光はステージだけ
- **タイポグラフィ**: §5.2。Noto Sans JP の 400 / 500 / 700 と Hack。本文 14/24
- **余白**: 4px グリッド。上部バー 52、左ナビ 216、右レール 344、カード内 20、セクション間 32
- **コンポーネント**: 明るい面は 1px 罫線と余白、影はダイアログとトーストだけ。主キーは墨の塗り。ステージは線画 + 光
- **長所**: 不満（暗色が平均的）に正面から答える。入力モニターが機能的に最も読める。面の切替が状態の意味になる。コントラスト管理が面ごとに閉じる。CSS のスコープ変数（`[data-surface="stage"]`）で実装できる
- **短所**: トークンが 2 スコープになり、明るい面と暗い面の橋渡し（線・字・余白）を揃えないとちぐはぐになる。将来ダークテーマを作る場合、思想が衝突する（§9）
- **8BitDo Ultimate 2 に固有か**: **高い。** 「光は暗い所でだけ意味を持つ」という物理から面の構成が導かれている。他製品の画面に置き換えると、暗いステージの必然性が消える

### 3.4 比較と選定

| 観点 | A 昼の作業台 | B 刻印と打刻 | C 昼の作業台と夜のステージ |
| --- | --- | --- | --- |
| 不満への回答 | 中（明るくはなるが既定解） | 中（質感は出るが暗色の不満と無関係） | **高（明度を機能で分ける）** |
| 3 つの仕事への適合 | 高 | 中（フォームが弱い） | **高（確認を右レールに固定）** |
| 固有性 | 低 | 中 | **高** |
| 実装リスク | 低 | 高（部品の自作が多い） | 中（スコープが 2 つだけ） |
| 判定 | 不採用（作法だけ継承） | 不採用（打刻の組版だけ継承） | **採用** |

**選定理由**は 3 つです。第一に、3 案のうち「明るい作業面」と「光が意味を持つ暗い面」を同時に成立させられるのは C だけです。第二に、確認（書き込み前の安全確認）を右レールに固定すると、3 つの仕事のうち最も事故につながる (c) が常に画面に残ります。第三に、トークンは 2 スコープですが、境界は「入力モニターだけ」に限定されるため、実装とレビューの範囲が閉じます。

A の規律（罫線・余白・装飾の削除）と、B の「値は打刻（等幅・桁揃え）」だけを内部作法として取り込みます。刻印のテクスチャ・影・紙の色は使いません。

## 4. 方向性の定義（Direction 5 行）

- **Product**: **Padbench**（8BitDo Ultimate 2 対応）の現在値を読み、設定・リマップ・マクロを編集し、書き込む前に確認する OSS デスクトップツール
- **Character**: 静か、正確、必要な所だけ灯る
- **World**: 昼の作業台（白い面、細い罫線、等幅の数値）と、暗い部屋で光るコントローラ
- **Moments**: ①入力モニターの暗いステージ（線画のコントローラと、押されたボタン・倒したスティックだけが灯る）②書き込み前の確認（変更点が現在値 → 変更後で並び、危険な変更だけが赤で出る）
- **Signature**: **面の二重性。** 読む・書くは明るい面、見る（入力）は暗い面。明るさが仕事の種類を語る

この 5 行から外れる要素は入れません。グラデーション、発光する枠線、絵文字、イラスト、ロゴ画像、意味のないアイコンは使いません。

## 5. トークン仕様

### 5.1 色

#### 5.1.1 ルール（先に決める）

1. **正常は色を使わない。** 接続済み・一致・完了は無彩色（墨と灰）で表す。色は注意と異常にだけ使う
2. **アクセントは 1 つ。** 選択・フォーカス・現在のタブにだけ青緑を使う。状態表示には使わない
3. **光は暗い面だけ。** LED のシアンは入力モニターのステージ内でのみ使う。明るい面では使わない（コントラストが取れないため）
4. **面の差は 1.2〜1.5:1、操作の輪郭は 3:1 以上。** 構造線と操作線を別トークンにする
5. **グラデーション・カラーの影・発光する枠線は使わない。** ステージの光は 1 層のぼかし（`box-shadow`）までとし、装飾ではなく状態（点灯・未受信）にだけ使う

#### 5.2.3 言語切替

- `:root` に `lang="ja"`、英語時は `lang="en"` を付ける。`:lang()` でフォントの微調整（英字の tracking）を行う場合だけ使う

- 文字列は連結しない（語順が変わるため）。i18n のキーは 1 対 1 とし、未翻訳キー 0 をテストで固定する（P6）
- 英語の見出しは Title Case にしない（アプリの他用語と揃えるため Sentence case）

### 5.4 レイアウト

#### 5.4.1 構図

上部バー、左ナビ、コンテンツ、右レールの 4 領域です。右レールは「見る・確認する」専用で、画面によって中身が変わります。

```text
┌──────────────────────────────────────────────────────────────┐
│ 上部バー 52: アプリ名 / 状態 / 接続先 / 言語 / 設定            │
├──────────┬───────────────────────────────┬───────────────────┤
│ 左ナビ   │ コンテンツ（最大 720）         │ 右レール 344       │
│ 216      │                               │                   │
│ 接続     │ h1 24/34                      │ デバイス画面:      │
│ 現在値   │ 説明 14/24                    │  入力モニター      │
│ 設定     │ カード（1px 罫線 / 角丸 12）   │  （ダークステージ）│
│ リマップ │ 表（36 行）                    │                   │
│ マクロ   │                               │ 設定画面:          │
│ ログ     │                               │  書き込み前の確認  │
│ ─────    │                               │  （ライト）        │
│ ライセンス│                              │                   │
└──────────┴───────────────────────────────┴───────────────────┘
```

- 上部バー: 左にアプリ名（`text-ui` 500）と「書き込み対応版」（`text-meta` muted）。右に状態（ドット + 状態名）、接続先名、言語切替、設定。状態は上部バーに 1 つだけ置き、ナビや本文で繰り返さない
- 左ナビ: 現在の画面は `--accent-soft` の地 + 左 2px `--accent`、ラベルは `--text`。非選択は `--text-2`。下部にライセンスと接続先の要約（デバイス名 / アドレス / MTU）
- コンテンツ: `h1` + 説明 1〜2 文 + カード。カードは 1 画面 2〜3 枚まで。カードを増やすより、セクション見出しと罫線で分ける
- 右レール: デバイス画面は入力モニター（ステージ）、設定 / リマップ / マクロ画面は書き込み前の確認。右レールは `position: sticky`（`top: 52px + 20px`）で、コンテンツが長くても確認が画面に残る
- 余白: コンテンツ列の右に 24px 以上の余白を残し、右レールとの間に縦ヘアラインを 1 本引く。右端を埋めない

#### 5.4.2 ブレークポイント

| 幅 | 構成 |
| --- | --- |
| **1180 px 以上** | 左ナビ 216 + コンテンツ（最大 720）+ 右レール 344 |
| **900〜1179 px** | 左ナビ 216 + コンテンツ。**右レールはコンテンツの下に移動**し、幅いっぱいのブロックになる（入力モニターは横長、確認パネルは通常幅） |
| 900 px 未満 | 非対応（Tauri の `minWidth: 900`）。横スクロールは出さない |

- 1180 px でコンテンツは `1180 − 216 − 344 = 620` px（内側 24 × 2 を引いて実質 572 px）。720 px の最大幅は 1280 px 以上で効く
- 1440 px 以上では、コンテンツ列を `margin-inline: auto` で中央に寄せ、右レールは右端に固定する。余白は左右に均等に配るのではなく、コンテンツの右側に寄せる（視線が本文と確認の間で往復するため）

#### 5.4.3 最小 900×620 での崩れ方

```text
900 × 620（右レールは下部へ）
┌────────────────────────────────────────────┐
│ 上部バー 52（アプリ名は 1 行、言語は「JA」） │
├──────────┬─────────────────────────────────┤
│ 左ナビ   │ コンテンツ 636（内側 24）        │
│ 216      │  スクロール                     │
│          │                                 │
│          ├─────────────────────────────────┤
│          │ 入力モニター 200（横長ステージ） │
└──────────┴─────────────────────────────────┘
```

- 幅 900: コンテンツは 636 px。表は列の優先度で落とす（残す: ラベル / 現在値 / 変更後。隠す: 補足 / 単位。隠した値は行の展開で見せる）
- 幅 900 で上部バー: アプリ名は `max-width: 180px` + `truncate`、状態はドット + 状態名（「接続済み」）、接続先名は隠して状態のツールチップに含める。言語は `JA / EN` の 2 ボタンではなく 1 つのセグメント（幅 64）
- 高さ 620: 上部バー 52 は固定、コンテンツとナビは独立スクロール。右レール下段のステージは 240 → 200 px に縮め、数値の行を 2 列から 1 列に落とす
- 高さ 620 でダイアログ: 幅 `min(560px, calc(100vw - 48px))`、高さ `max-height: calc(100dvh - 64px)`、本文だけスクロール、フッターは固定
- 200% ズーム: 実効幅 450 px 相当になるため、最小幅では 1 列レイアウトに落ちる。`rem` 基準で組み、`px` 固定の幅を書かない（上部バー 52 px などの寸法は `rem` 換算値 `3.25rem` を使う）

#### 5.4.4 スクロールと重なり

- `html, body { height: 100dvh; }`（`h-screen` は使わない）。アプリ全体は `overflow: hidden`、スクロールするのはナビとコンテンツだけ
- `min-width: 0` をフレックスの子に必ず付ける（長い日本語・パスで列が壊れるのを防ぐ）
- z-index は 5 段だけ: `0` 基本 / `10` sticky ヘッダー / `20` ポップオーバー・セレクト / `30` トースト / `40` ダイアログのオーバーレイ / `50` ダイアログ
- スクロールバーは `scrollbar-gutter: stable` で幅の揺れを防ぐ。ステージの canvas は DPR を反映して 2 倍で描く

### 5.5 コンポーネント

すべての部品に **default / hover / focus-visible / active / disabled / loading / error / empty** の状態を定義します（TAURI_PLAN.md §9.1）。「loading」は操作部品では「処理中」、一覧では「行のプレースホルダー」を指します。

#### 5.5.1 ボタン（primary / secondary / danger）

| 種類 | 地 | 輪郭 | 文字 | 用途 |
| --- | --- | --- | --- | --- |
| primary | `--ink-fill` | なし | `--on-ink` 13/500 | 1 画面に 1 つ。接続する / 読み込む / 書き込む |
| secondary | `--surface-panel` | 1px `--line-strong` | `--text` 13/500 | 再試行、コピー、キャンセル、閉じる |
| danger | `--surface-panel` | 1px `--danger` | `--danger` 13/500 | 復元、初期化（取り消せない操作） |

- 高さ 32 px、左右 14 px、角丸 6、`gap: 6`
- hover: primary は地 `#2A3138`、secondary は地 `--surface-hover`、danger は地 `--danger-soft`
- active: 地を 1 段暗く（primary `#0B0E10`、secondary `--surface-active`）
- focus-visible: `--focus-ring`（2px + 2px の二重リング）。`outline: none` を単独で使わない
- disabled: 地 `--surface-sunken`、輪郭なし、文字 `--text-disabled`。**ボタンの上に理由を 1 行出す**（例: 「接続すると書き込めます。」）。disabled のまま押せる見た目にしない
- loading: ラベルの左に 12px のインラインスピナー（`prefers-reduced-motion` では静止した円）。**ラベルは変えない**（「書き込む」→「書き込んでいます…」はボタンではなく直下の進行行に出す）
- danger の塗り（`--danger-fill` + 白文字）は、確認ダイアログの最終ボタンだけ。一覧やツールバーに出さない

#### 5.5.2 入力（テキスト・数値）

- 高さ 32、地 `--surface-panel`、輪郭 1px `--line-strong`、角丸 6、左右 10、文字 13/20
- 数値入力は Hack 12 で桁を揃える。`inputmode="numeric"`、`min` / `max` / `step` を必ず付ける（デッドゾーンは 0〜127、外側は 0〜128、振動は 0〜1.0 を 0.2 刻み）
- プレースホルダーは `--text-muted`（4.5:1 以上）。例の値は書かない（実値と誤読するため）。代わりにラベルの下に範囲を `--text-meta` で書く
- hover: 輪郭は変えず地を `--surface-hover`。focus: 輪郭 `--accent` + `--focus-ring`。error: 輪郭 `--danger` + 直下に 12px `--danger` の文言（`aria-describedby`）。disabled: 地 `--surface-sunken`、文字 `--text-disabled`
- ラベルは必ず `<label for>` で結び、クリックでフォーカスする。必須・範囲はラベル側に書く（例: 「内側デッドゾーン（0〜127）」）

#### 5.5.3 スイッチ

- トラック 36×20、角丸 full、つまみ 16 px 白 + `--line` の 1px 輪郭
- off: 地 `--surface-sunken` + 輪郭 1px `--line-strong`（輪郭で 3:1 を確保）。on: 地 `--accent` + 輪郭なし。つまみは `translateX(16px)`、`transform` のみを 160 ms で動かす
- 右側に状態を `--text-meta` で書く（「オン」「オフ」）。色だけで状態を伝えない
- 実装は `<button role="switch" aria-checked>`。キーボードは Space / Enter。ラベルは `<label id>` と `aria-labelledby` で結ぶ

### 5.6 入力モニター（ライブ入力）の描画仕様

入力レポートは `cmd=0x0003` の 12 バイトです（[docs/PROTOCOL_SPEC.md](PROTOCOL_SPEC.md) §7.2）。座標の生値は次のとおりです。

| フィールド | 生値 | 正規化 |
| --- | --- | --- |
| `LeftStick_X` / `LeftStick_Y`（`+0x04` / `+0x05`） | u8、中心 127 / 128 | `n = clamp((raw − 127) / 127, −1, +1)` |
| `RightStick_X` / `RightStick_Y`（`+0x06` / `+0x07`） | 同上 | 同上 |
| `Trigger_R`（`+0x08`）/ `Trigger_L`（`+0x09`） | u8、0〜255 | `t = raw / 255`（0〜1） |
| `Battery`（`+0x0A`） | u8、**スケール未確認** | % に換算しない。生値のまま表示する |

#### 5.6.1 Y 軸は上が正

画面座標は下が正なので、正規化した `ny` を描画するときに符号を反転します。

```text
x_screen = cx + nx * r
y_screen = cy − ny * r        // ny が +1 のとき画面の上端
```

- **生値の Y の向きは実機で未確認**です。プロトコル仕様は中心値と `val − 127` だけを定義しており、上方向が + か − かを断定していません。したがってアダプタ層に定数 `Y_SIGN: +1 | −1` を置き、**実機で 1 回だけ確認してから固定**します。推測で符号を決めません
- 符号の反転はアダプタ層で 1 回だけ行う。コンポーネントごとに反転しない（二重反転を防ぐ）
- 同じ値から描画する要素（点・軌跡・数値）は、必ず同じ正規化値を使う

#### 5.6.2 描画

- **スティック**: 径 160 px の円。外周 1px `--stage-line-strong`、十字線 1px `--stage-line`、デッドゾーンの円 1px 破線 `--stage-line-strong`（設定の `left_start` / `right_start` を 127 で割った比）
- 現在位置は径 10 px の点 `--stage-led` + `box-shadow: 0 0 12px rgba(111,231,216,.28)` の 1 層だけ。点滅・脈動はしない
- 軌跡は直近 8 点（約 33 ms 間隔）を折れ線で描き、α を 0.35 → 0.02 に逓減する。止まっているときは軌跡を消す（動いた事実だけを残す）
- **トリガー**: 横バー。高さ 6 px、角丸 full、地 `--stage-line`、値は `--stage-led`。バーの右に数値（Hack 12、`0.62`）と単位なしの 0〜1 表記。L2 / R2 を縦に 2 本並べる
- **ボタン**: 22 ボタンをコントローラの線画上に配置する。非押下は輪郭のみ `--stage-line-strong`、押下は塗り `--stage-led` + 同じ 1 層の光。押されたボタン名は下の一覧にもテキストで出す（色だけに頼らない）
- ステージの外枠は角丸 12、地 `--stage-bg`、内側 20。ヘッダー（「入力モニター」+ 受信レート）とフッター（「最終受信 12 ms 前」）はステージの外側に置き、文字はライト面のトークンで組む（暗い面に暗い文字を置かない）

#### 5.6.3 60fps と補間

- 通知は 20 ms 間隔（TAURI_PLAN.md §3.1）。描画は `requestAnimationFrame` のループで行い、React の再レンダーは 1 フレームに 1 回もしない（`useRef` に最新値を持ち、canvas に描く）
- 補間: `s = 1 − exp(−dt / τ)`、`display = display + (target − display) * s`。τ はスティック 45 ms、トリガー 60 ms。追従の遅れは最大でも 2 フレーム程度に収める
- 数値の表示は **10 Hz（100 ms）** で更新する。点の動きは 60fps でも、数字が毎フレーム変わると読めないため
- ボタンの押下は補間しない（押した瞬間に点灯、離した瞬間に消灯）。押下時間が 1 フレーム未満でも、最低 1 フレームは点灯させる
- 入力が止まったら、500 ms で「入力が止まっています」を `--stage-amber` の 1 行で出す。2 秒で点を `--stage-danger` に変え、フッターに「最終受信 2 秒前」を出す
- 1 フレームの描画予算は 4 ms。超える場合は軌跡の点数を 8 → 4 に落とす（品質設定ではなく自動の段階）
- `prefers-reduced-motion: reduce` では補間をやめて最新値にスナップし、軌跡を出さない。機能（値の更新）は止めない

#### 5.6.4 アクセシビリティ

- canvas は `aria-hidden="true"`（装飾）。数値は DOM のテキストで出す（スティック X/Y、トリガー、押下ボタン名、受信レート、最終受信）
- 数値のライブ更新は `aria-live` にしない（毎秒 10 回読み上げられるため）。代わりに「現在の値を読み上げる」ボタンで 1 回だけ要約を読む（`aria-live="polite"` の領域に流す）
- キーボードでモニターの一時停止ができる（`P` キー）。一時停止中は「一時停止中」を表示し、最終値のまま止める

### 5.7 モーションと応答性

#### 5.7.1 時間と曲線

| token | 値 | 用途 |
| --- | --- | --- |
| `--dur-0` | 0 ms | reduce-motion 時 |
| `--dur-1` | 90 ms | hover、押下、色の変化 |
| `--dur-2` | 160 ms | タブ下線、スイッチ、ポップオーバー |
| `--dur-3` | 240 ms | ダイアログ、トースト、バナーの出入り |
| `--ease-standard` | `cubic-bezier(0.2, 0, 0, 1)` | すべての UI 遷移（1 本だけ） |
| `--ease-linear` | `linear` | 進捗バー、スピナー |

- アニメーションするのは `transform` / `opacity` / `background-color` / `border-color` だけ。`width` / `height` / `top` / `left` / `margin` / `padding` は動かさない
- 入場アニメーションはダイアログとトーストだけ（`opacity` + `translateY(4px)` → 0）。ページ読み込み時のアニメーションはしない
- ループする動きはスキャン中のドット（1.2 秒の明滅）とスピナーだけ。どちらも止められる
- `transition: all` は書かない。対象プロパティを列挙する

#### 5.7.2 reduce-motion

```css
@media (prefers-reduced-motion: reduce) {
  :root { --dur-1: 0ms; --dur-2: 0ms; --dur-3: 0ms; }
  .scan-dot { animation: none; }
}
```

- JS 側でも `matchMedia('(prefers-reduced-motion: reduce)')` を読み、入力モニターの補間と軌跡を無効化する
- スキャン中の点滅は静止した `--warning` のドットに、スピナーは静止した円 + 「処理中」の文字にする
- 動きを止めても、状態（押下・点灯・エラー）は必ず残す。動きだけに意味を持たせない

#### 5.7.3 応答しない問題への対策

| 時間 | 表示 | 実装 |
| --- | --- | --- |
| 0 ms | 押下状態（即時） | `:active` の色変化。IPC を待たない |
| 100 ms 以内 | 受理の表示 | ボタン直下に進行行（「書き込みを準備しています…」） |
| 400 ms | 待機の明示 | 進行行を「応答を待っています…」に変える。スピナー + 経過時間 |
| 2 秒 | 中止の提示 | 「中止する」ボタン + 何を待っているかの 1 文 |
| タイムアウト | 失敗として確定 | インラインのエラー（行為の近く）+ 「再試行」+ 詳細の折りたたみ |

- 無効化は必ず理由を添える（「接続すると書き込めます。」「記録中は書き込めません。」）
- 書き込み中は operation lock を UI でも表す: ナビ移動は許可、設定の編集と書き込みボタンはロック、上部バーに「書き込み中」を出す
- 接続断は fail-closed。切断を検知したら操作を無効化し、上部バナーに「接続が切れました。」+「再接続する」（命令形は使わない）
- 進行中の操作は画面を離れても止めない。戻ったときに同じ進行行が出る（状態は Rust 側が正）

## 6. 日本語コピーの原則

### 6.1 文体

- **本文・説明・エラーは「です・ます」**で統一する。体言止めにしない（「現在値を読み込みます。」）
- **ラベル・見出し・ボタンは体言止めか動詞句**。「書き込む」「現在値」「入力モニター」。文末に「。」を付けない
- **手順は「〜します」**、利用者への依頼は「〜してください」。敬語を重ねない（「〜していただけますでしょうか」は使わない）
- 1 人称・2 人称は書かない（画面が主語）。「あなたのデバイス」ではなく「接続先のデバイス」
- 進行中は「〜しています…」（三点リーダ 1 つ）。例: 「設定を書き込んで検証しています…」
- 感嘆符は使わない。「！」を重ねない

### 6.2 句点・読点・表記

- **句点「。」**: 本文・説明・エラーには付ける。ボタン・ラベル・見出し・表セル・1 文のトーストには付けない。2 文以上になったら付ける
- **読点「、」**: 短い文の頭（「今日は、」）と「を」の後には打たない。長い前置きの後と、誤読する箇所だけに打つ
- **括弧**: 全角「（）」。コード・パス・コマンドは半角のまま
- **中黒「・」**: 並列のみ。文の区切りに使わない
- **三点リーダ**: 「…」1 つ（「...」は使わない）
- **数字**: 半角。単位は半角スペース区切り（`2768 バイト`、`20 ms`、`64 %`）。16 進は `0x` + 大文字（`0x0AD0`）。範囲は「0〜127」
- **和文と英数字の間**: 半角スペース 1 つ（「設定 2768 バイト」「MTU 200」「App Mode で接続」）
- **コロン**: 日本語 UI では使わない。「受信レート: 60 回/秒」ではなく「受信レート 60 回/秒」
- **バッククォート**: 画面には出さない。文書（README 等）でのみコードを囲む
- **ボタンのラベル**: 12 文字以内。折り返さない
- **本文の長さ**: 1180 px ウィンドウのコンテンツ幅は 572 px（実測）で、14 px の和文は 1 行約 40 文字。説明文は 40〜80 文字（2 行以内）に収める。助詞や語の途中で折り返す文（「確認パ/ネル」）を書かない。`text-wrap: pretty` と `line-break: strict` を併用し、未対応の WebView では文を短くして調整する（モックアップで実測）
- **エラー**: 「何が起きたか」+「理由」+「次にすること」の順。利用者を責めない

## 7. 実装規約

### 7.1 技術前提

- React + TypeScript + Vite + Tailwind CSS（TAURI_PLAN.md §2。P0 雛形は React 19 / Tailwind v4 / vitest）。スタイルは Tailwind のユーティリティだけにせず、**デザイントークンを CSS 変数**（`apps/desktop/src/styles/tokens.css` に分離する予定。現状は `apps/desktop/src/index.css` の `@theme`）に置き、Tailwind v4 の `@theme` で同じ名前を参照する
- 画面の状態は Rust 側を正とする。Web UI は表示用のモデルだけを持つ（TAURI_PLAN.md §3.1）
- 入力モニターは events を受けて `useRef` + canvas に描く。React の state 更新を毎通知で行わない
- 書き込みの確認状態を IPC で受け取らない（TAURI_PLAN.md §3.2）。UI のチェックボックスは操作の補助で、Rust 側が最終判断する

### 7.2 Tailwind への写像（例）

```css
@import "tailwindcss";

@theme {
  --color-bg: #F4F6F7;
  --color-panel: #FFFFFF;
  --color-sunken: #EDF0F2;
  --color-line: #D6DCE0;
  --color-line-strong: #7C868F;
  --color-ink: #15191C;
  --color-text: #15191C;
  --color-text-2: #3A434B;
  --color-muted: #5B656E;
  --color-disabled: #646E78;
  --color-accent: #0B6A63;
  --color-accent-soft: #E3F1EF;
  --color-warning: #8A5200;
  --color-warning-soft: #FDF4E3;
  --color-danger: #AE2418;
  --color-danger-soft: #FCEFEE;
  --color-danger-fill: #A3211A;
  --radius-sm: 6px;
  --radius-md: 8px;
  --radius-lg: 12px;
  --font-ui: "Noto Sans JP", system-ui, sans-serif;
  --font-data: "Hack", ui-monospace, monospace;
}
```

- 任意値（`p-[13px]`、`z-[999]`、`rounded-[7px]`）を書かない。スケール外の値が必要なら、先にトークンを追加する
- 影は `--shadow-pop` の 1 つだけ。`shadow-md` などの既定影を直接使わない
- ステージは `data-surface="stage"` のスコープで変数を上書きする

### 7.3 アクセシビリティ

- ランドマーク: `<header>`（上部バー）、`<nav aria-label="画面">`、`<main>`、`<aside aria-label="入力モニター">`
- 現在の画面は `aria-current="page"`。見出しは `h1` → `h2` → `h3` の順を飛ばさない
- フォーカスは常に見える（`:focus-visible` + `--focus-ring`）。`outline: none` を単独で使わない
- タブ・スイッチ・ダイアログはネイティブ要素 + ARIA パターンで実装する。追加の UI プリミティブ依存を入れる場合は、ライセンス表記（[THIRD_PARTY_LICENSES.md](../THIRD_PARTY_LICENSES.md) と [NOTICE](../NOTICE)）を同じ PR で更新する
- トーストとバナーは `aria-live="polite"`。エラーは操作した場所の直下に出す
- 画像・図形は `alt` か `aria-hidden` を明示する。アイコンだけのボタンには `aria-label` を付ける
- キーボード: Tab 移動、Enter 確定、Esc で閉じる、矢印キーでタブ。フォーカスを永久に失う操作を作らない
- `color-scheme: light` を `:root` に宣言する（OS のダーク設定でネイティブ部品が暗転するのを防ぐ）

### 7.4 検証

- コントラスト: §5.1.5 の値をテストで固定する（例: `apps/desktop/src/tokens.test.ts`（vitest）で `contrast(text, surface) >= 4.5`、`contrast(lineStrong, surface) >= 3`）。値の変更はテストの変更を伴う
- レイアウト: 900×620 / 1024×768 / 1280×800 / 1920×1080 / 200% ズームで、横スクロールが出ないことを確認する
- キーボード: 主要操作（接続、読み込み、設定変更、書き込み確認、ダイアログ、トースト）を Tab だけで完了できる
- reduce-motion: OS 設定を `reduce` にして、点滅・スライド・補間が止まり、状態が残ることを確認する
- モックアップ: [docs/design/mockup.html](design/mockup.html) を `file://` で開き、2 状態が崩れないことを確認する（[design/README.md](design/README.md)）

## 9. 未決事項

- **Y 軸の符号**: 生値の Y が上方向に + か − かは実機未確認。`Y_SIGN` を設定に持ち、実機で 1 回確認してから固定する（§5.6.1）
- **ダークテーマ**: 今回はライト固定。将来ダークを作る場合、入力モニターは既に暗いため「明るい面だけを反転する」ことになり、思想（面の二重性）が壊れる。作るなら別案として設計する
- **フォントの woff2 サブセット**: 既存の `crates/eightbitdo-gui/assets/fonts/build_fonts.py` を Web 用に拡張する。日本語の全 UI 文字を 3 ウェイトで覆うこと、`font-display: swap`、preload の対象を決める
- **アイコン**: 今回は文字と最小限のインライン SVG だけ。アイコンセットを入れるなら 16px・1.5 stroke の 1 セットに限定し、ライセンス表記を更新する
- **入力モニターの拡大表示**: ステージを全画面にしたときのレイアウト（コントローラ線画の拡大、数値の配置）は P2 で決める
- **英語コピーの確定**: 用語対応は §6.3 の最小限のみ。P6 で全キーの英語を確定する
- **書き込み中のナビ移動**: 許可する方針にしたが、画面を離れたときの進行表示の位置（上部バーかトーストか）は P3 で決める
