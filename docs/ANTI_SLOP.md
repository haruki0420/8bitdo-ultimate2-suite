# AI スロップを避ける方法（調査と運用ルール）

- 作成: 2026-11-23
- 目的: 「量産的」「AI が作った感じ」を**主観で争わず**、判断と検証の手順に落とす
- 適用対象: Padbench のデスクトップ（Tauri）、モバイル（Kotlin / Swift）、および今後追加する画面
- 位置づけ: 本ドキュメントは**方法論**。具体的な色・タイポ・レイアウトの正本は [DESIGN_TAURI.md](DESIGN_TAURI.md) と [design/mockup.html](design/mockup.html)

---

## 0. 結論（先に要点）

1. **スロップの原因は「判断の不在」**。モデルは指示が無いと学習分布の平均（無難な白＋青、角丸カード、Inter 風見出し）へ回帰する。能力の問題ではなく、**決めていないこと**が原因。
2. 対策は「禁止リスト」だけでは足りない。**方向を 1 回決めて（5 行）、全パスをその方向に従わせ、最後にテンプレ置換テストで検証する**。
3. 良し悪しは属人的なので、**機械で検出できる兆候**（グラデ・絵文字・アクセント数・余白スケール・コントラスト・禁止語）をテストにし、残りをレビュー観点にする。
4. このリポジトリでは、**画面ごとに「1 つの明るい瞬間」と「署名の細部」を必須**にし、無い画面は未完成として扱う。
5. 日本語 UI は別軸のスロップ（直訳・用語の不統一）が出る。**用語集と `nihongo` 基準**を独立に通す。

---

## 1. なぜ AI 生成 UI は量産的に見えるのか

外部の分析でも原因は一致している。

- **統計的平均への回帰**: 指示が無いとモデルは「よくある見た目」の確率質量へ寄る。白いカード＋グレー背景＋単一の青、角丸 8〜12px、Inter 風フォント、紫→青グラデがその代表。[vibecodekit](https://vibecodekit.dev/ai-slop-design) は「スロップの本当の原因は判断の不在」と表現している。
- **自己評価が苦手**: 「良い UI か」を自分で採点させても、分布が縮んでもスコアが動かない。生成的均質性はモデルの能力向上だけでは解けない。[design-agent.dev の分析](https://design-agent.dev/blog/2026-10-15-ai-slop-measuring-design-homogenization/) はこの構造を指摘している。
- **装飾がクロームに漏れる**: 色・光・影・絵文字が、内容ではなくナビ・ボタン・枠・ラベルに散る。結果、どの製品にも見える。[unslop](https://x.com/heydamir) は「richness は 1〜2 の内容の瞬間に置き、クロームは静かにする」と定式化している（CC BY 4.0、作者 Damir Sokolovsky）。
- **検証が主観**: 「なんか安っぽい」で終わると直らない。兆候を列挙し、修正し、再描画して突き合わせる手順が必要。[AI-Slop Checklist](https://standoutmcp.io/guides/fix-vibe-coded-ui-checklist)、[no-slop-ui](https://github.com/LeoStehlik/no-slop-ui)。

## 2. 検出チェックリスト（兆候 → 修正）

以下は**機械検出できるもの**と**目視・レビューで見るもの**に分ける。

### 2.1 機械で検出する（テスト / grep / CSS 検査）

| 兆候 | 検出方法 | 合格条件 |
| --- | --- | --- |
| 色相グラデーション（面・文字・光彩） | `gradient` の grep、CSS 変数検査 | 0 件（同一色相内の微小な明度差のみ許可） |
| アクセント色の乱立 | 色トークンの列挙 | クロームのアクセントは 1 色のみ |
| 絵文字をアイコン代わりに使用 | 絵文字コードポイントの検査 | 0 件（線画 SVG のみ、16px / 1.5 stroke） |
| 紫・ネオンの使用 | 色相の検査 | 使用しない |
| 過剰な影・グロー・カラーブラー | `box-shadow` / `filter: blur` の検査 | 影はダイアログ・トーストの 1 種のみ |
| 4px グリッド外の余白 | 任意値（`[...px]`）の grep | 0 件 |
| 角丸の量産（`rounded-full` の多用） | クラス集計 | スイッチ等の形状に限定 |
| 12px 未満の文字 | サイズトークン検査 | 最小 11px（データ補助のみ） |
| コントラスト不足 | 実測計算 | AA: 本文 4.5:1、大文字 3:1、操作輪郭 3:1 |
| 用語の不統一・禁止語 | 用語集テスト | 録音/ライブ入力/設定値 等の旧語 0 件 |
| 未検証の主張 | コピーのレビュー + grep | 「完全」「絶対」「10x」等の断定なし |

> 実装済みの例: `apps/desktop/src/**/*.test.ts` に、グラデ禁止・絵文字禁止・単一アクセント・コントラスト・用語集のテストがある。**画面を追加したら同じテスト群に項目を足す**。

### 2.2 目視・レビューで見る（機械化が難しい）

- **テンプレ置換テスト**: 製品名を他社製品に置き換えても成立する画面は、まだ方向が弱い（unslop の最終チェック）。
- **1 つの明るい瞬間**があるか。色・材料・光が内容のどこかに集中しているか（無ければ未完成）。
- **署名の細部**が 1 つだけ、一貫して使われているか（2 つ以上は散らかる）。
- クローム（ナビ・ボタン・枠）が静かか。内容より目立っていないか。
- 空状態・エラー・読み込み・無効の**8 状態**が設計されているか。
- 数値の桁揃え（`tabular-nums`）と書式の統一。
- 見出しが「何の画面か」を言っているか（`ようこそ！` 等の挨拶は禁止）。
- モーションが意味を説明しているか（ループ・跳ね・`transition-all` は禁止）。
- 日本語: 直訳調でないか、助詞が抜けていないか、用語が統一されているか。

## 3. 回避のプロセス（順序が重要）

### 3.1 方向を 5 行で決める（実装前に）

1. **Product**: 何を、誰のために。
2. **Character**: 具体的な 2〜3 語（「静か」「正確」「少し温かい」）。「モダン」「ミニマル」「プレミアム」は禁止（どのテンプレにも当てはまるため）。
3. **World**: その製品が自然に属する場所・素材（紙とインク、計測器と夜勤、地図と窓の光）。
4. **Moments**: 色・材料・光を集中させる 1〜2 か所（内容側）。
5. **Signature**: この製品だけの小さな細部 1 つ。

方向が決まるまで実装しない。決めた方向は文書に固定し、変更には理由を書く。

### 3.2 9 パスで直す（unslop の手順）

1. 余白（4px グリッド、同種同サイズ、グルーピング）
2. 色（1 つのニュートラルランプ、3 つの文字役割、1 アクセント）
3. アイコン（1 セット・1 サイズ・1 ストローク、絵文字排除）
4. コピー（具体的・短い・誇張なし・未検証の主張なし）
5. タイポ（キャラクタに合う 1〜2 ファミリ、400〜600、階層はサイズと色で）
6. レイアウト（アプリの比率、中央寄せ縦積みの回避、非対称の活用）
7. 細部（入れ子角丸、状態、フォーカスリング、数値書式）
8. ビジュアル（製品自身の内容で見せる。装飾の詰め物をしない）
9. モーション（意味のある動きのみ、1 イージング、ループ禁止）

### 3.3 検証してから完了

- 2 サイズ（1280×800 / 900×620）で**実際に起動してスクリーンショット**。
- 兆候リストと突き合わせ、残っていれば直す。
- 独立レビュー（Tier 2/3）で「テンプレ置換テスト」と「1 つの明るい瞬間」を確認。

## 4. このリポジトリでの運用ルール

1. **画面追加時**: 方向 5 行（既存の方向のどこに属するか）+ 明るい瞬間 + 署名を PR 本文に書く。無い PR はレビューで差し戻す。
2. **テスト追加**: 画面ごとに、グラデ 0・絵文字 0・アクセント 1・コントラスト AA・用語集一致・4px グリッドのいずれかを自動テストに含める。
3. **レビュー**: `design-review` 相当の観点で、兆候リストとテンプレ置換テストを確認する。
4. **日本語**: `nihongo` 基準と用語集（[DESIGN_TAURI.md](DESIGN_TAURI.md) §6.3）を独立に通す。機械テストは禁止語のみ。
5. **禁止リスト（この製品で使わない）**: 色相グラデーション、紫・ネオン、絵文字アイコン、ガラスモーフィズム、過剰な角丸カード、意味のないバッジ（`PRO` `New`）、挨拶見出し、`Welcome back!`、`seamless` 等の誇張、未検証の数値主張、`transition-all`、ループアニメーション。

## 5. Padbench への適用（現時点の方向）

- **Product**: コントローラの現在値・設定・マクロ・書き込みを扱う計測ツール。
- **Character**: 静か、正確、少し硬質。
- **World**: 製図台と計測器（紙の面・細い罫・寸法線・等幅の数値）。
- **Moments**: 入力モニターのダークステージ（光は暗所でだけ意味を持つ）、書き込み前の確認レール。
- **Signature**: 図面番号・寸法注記風のメタ表記（例: `§2 / 0x0003`）と、等幅の桁揃え数値。

> この方向は「白いカード UI」を捨てる前提。現行実装がまだカード的なら、方向に合わせて作り直す。
