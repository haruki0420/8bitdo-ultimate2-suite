# 独立レビュー Tier

PR のリスクに応じてレビューの深さを変えます。目的は「docs に重すぎるレビューをしない」「危険な差分に軽すぎるレビューをしない」ことです。

## 1. Tier 判定

| Tier | 対象 | レビュアー | 範囲 | 故障リスト |
| --- | --- | --- | --- | --- |
| **1** | 通常の docs、コメント、整形、振る舞いを変えないリファクタ、テスト追加のみ | 1 本 | diff + テスト + リンク/コマンド | 振る舞いを変える場合のみ 1〜2 件 |
| **2** | 通常のコード、プロトコルのデータ構造・コマンドビルダー、CI/ツール（ゲート本体を除く）、プロセス文書 | 2 本（仕様検収 + 実装/回帰） | 変更ファイル + 直接の呼び出し側 + テスト | 3〜5 件 |
| **3** | 実機書き込み / Flash / OTA / CRC / オフセット / フレーミング / レビューゲート・セキュリティ / リリース / 大規模な混合差分 | 2 本 + 敵対的パス | 関連ファイル全体 + 呼び出し側 + モック | 10 件以上 + モックトランスポート検証 |

### 判定ルール

- **混合 PR は最大 Tier**（docs + code なら code の Tier）。
- 著者が PR で Tier を提案し、**レビュアーは昇格できる。降格はできない。**
- 迷ったら 1 段上に倒す。
- 行数は目安にしない。10 行の CRC 変更は Tier 3、1000 行の README 整形は Tier 1。
- 次のパスを含む PR は、docs だけであっても Tier 2 以上:
  - `AGENTS.md` / `CLAUDE.md`
  - `CONTRIBUTING.md` / `docs/REVIEW_TIERS.md` / `docs/BRANCH_PROTECTION.md`
  - `.github/**`
- 次のパスを含む PR は Tier 3:
  - `crc.rs` / `config_bt2.rs` のオフセット・CRC・マクロ Flash 関連
  - `commands.rs` の設定書き込み・マクロ・OTA コマンド
  - `boot` モジュール、OTA ステートマシン、ファームウェア API
  - `rulesets` / `review-gate` / リリース設定

## 2. Tier 1（軽量）

- レビュアー 1 本。
- diff 全体、関連テスト、リンク、コマンド例を確認する。
- 振る舞いを変えない docs/コメント/整形は、故障注入なし。
- テスト追加のみの PR は、対象コードに対する 1〜2 件の故障で「テストが落ちるか」を確認する。

## 3. Tier 2（標準）

- レビュアー 2 本。役割を分ける。
  - **仕様検収**: `docs/` との一致、オフセット、CRC、エンディアン、コマンド引数。
  - **実装/回帰**: API、エラー処理、境界値、呼び出し側、テストの抜け。
- 範囲は「変更ファイル + 直接の呼び出し側 + テスト」。変更ファイルだけを読んで終わらせない。
- 故障リストを 3〜5 件作り、それぞれ「どのテストが落ちるか」を記録する。

## 4. Tier 3（安全-critical）

- レビュアー 2 本 + **敵対的パス**。
  - 敵対的パスは、正常系の確認ではなく「仕様の矛盾」「境界値」「失敗系」「中断・再試行」「予約バイト破壊」を探す。
- 範囲は関連ファイル全体 + 呼び出し側 + モックトランスポート。
- 故障リストを 10 件以上作り、可能なら `cargo-mutants` などの自動変異も併用する。
- 実機書き込みを含む場合は、**書き込み前の 2768B バックアップ**と、モックでのパケット列・CRC・チャンク境界の検証を必須にする。
- OTA は「Erase → Write → Header → Save」の順序と、失敗時の `"8bt"` 復旧まで確認する。

## 5. 故障リストの書き方

件数を満たすことではなく、**検出したい故障を先に列挙**します。

| 故障 | 期待する検出 |
| --- | --- |
| CRC の多項式を `0x8408` ↔ `0xA001` で取り違える | CRC テストベクタ |
| `0x92C + slot * 0x0C` を `+ slot * 4` にする | SixAxis オフセットテスト |
| `align32` を `align16` にする | マクロ長テスト |
| RT/LT を入れ替える | マクロステップのバイト配置テスト |
| BLE RX に `0x04` プレフィックスを要求する | 受信フレーミングテスト |
| `cmd 0x0103` の 64B クランプを外す | チャンク分割テスト |
| OTA の最終チャンクを 64B 未満で送る | ファームウェア分割テスト |

PR には「故障 → 検出したテスト」の表を載せます。検出できない場合は、テストを追加するか、Tier を上げます。

## 6. レビュー記録

- レビュー結果は PR のレビューコメントに残す。
- レビューした head SHA に `review-gate` status を付ける（`docs/BRANCH_PROTECTION.md`）。
- 修正を push したら新しい SHA で再レビューする。前の SHA の status は引き継がれない。
- Tier と故障リストは PR 本文に残す。

## 7. 強制範囲

`main-protection` ruleset が強制するのは **`review-gate` status の存在** までです。Tier 判定・レビュー実施・故障リストの内容は手続きであり、write 権限者は迂回できます。強制力を上げる方法は `docs/BRANCH_PROTECTION.md` の「セキュリティ上の限界」を参照してください。
