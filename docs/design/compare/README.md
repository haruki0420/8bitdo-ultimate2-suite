## 7. 長所・短所

**A / 製図**

- 長所: 罫線・表・寸法線が数値の位置を固定するため、読み取りの往復が少ない。文字の最小は 5.19:1（補助）/ 7.62:1（本文）で AA を満たす。実装は罫線と表だけで、新しい素材を必要としない。入力モニターを暗いステージとして残せる。
- 短所: 図面枠・寸法線は他社の計測ツールにも付くため、造形の固有性は中程度。線が多く、状態色を足すと図面の規律が崩れやすい。長い日本語の注記は寸法線と干渉しやすい。

**B / 機器ラベル**

- 長所: 未接続の注意が最も速く見つかる（黒タブ + 橙帯）。状態 → 次の行動 → ボタンの順序が明快。罫線と塗りだけで実装できる。
- 短所: 2px の黒枠と黒タブが内容より強い（クロームが静かでない）。ラベルの言語はどの機器ツールにも貼れるため、テンプレ置換テストの耐性が最も低い。橙をページ地の文字に使えない（3.72:1）。

**C / 暗い計測器**

- 長所: 面が 1 つで破綻が少ない。彩度が計測値だけに乗るため、視線が数値に行く。彫り込みラベルの反復で計器の物質感が出る。
- 短所: 現行で否定された「暗色が平均的」という不満に対して、全面暗色を再導入する。日中の可読性は A より不利。信号色の用途が増えると計器ではなくなる。明るい作業面 + 暗いステージという二面性を失う。

## 8. テンプレート置換テスト

方法: 3 案の文言は同一なので、造形だけを対象に次の 3 置換を行う。置換後も画面が成立するほど、その造形は製品固有ではなくテンプレ的（弱い）と判定する。

1. 製品名 `Padbench` → `KeyTune`（架空のキーボード設定ツール）
2. `入力モニター` → `用紙送りモニター`
3. `書き込み前の確認` → `印刷前の確認`

| 置換 | A 製図 | B 機器ラベル | C 暗い計測器 |
| --- | --- | --- | --- |
| 製品名 | 成立（図面枠は計測一般に開く） | 成立 | 成立 |
| 入力モニター | 一部破綻（暗面の必然が消え、紙面だけが残る） | 成立（ラベルは何にでも貼れる） | 破綻（信号色の集中先が消える） |
| 書き込み前の確認 | ほぼ成立（0 件・差分は汎用） | 成立 | 成立 |
| 総合 | **中** | **低** | **中** |

- A: 造形の中心が「暗いステージ」と「確認レール」なので、製品名だけでは壊れない。ただし図面枠そのものは固有ではない。
- B: 3 置換すべてに耐える。これは長所（汎用）ではなく、**製品固有の造形がない**ことの裏返し。注意ラベルの情報順序だけが内容由来。
- C: ステージの信号色が造形の中心なので、機能名を替えると空洞化する。一方、暗い計器の言語自体は他社の計測ツールにもある。
- 3 案に共通して、`入力モニター`（22 ボタン・スティック 2・トリガー 2）と `書き込み前の確認`（0 件、差分、バックアップ）は Padbench 固有の仕事である。差が出るのは、その仕事を造形の中心に置けているかどうか。

## 9. 推奨案

**A / 製図を推奨する。** 主観ではなく、次の 5 基準で選んだ。A が最も強いのは 1・4・5、C が強いのは 3、B は 2 で最も弱い。総合で A とした。

1. **仕事への適合**: 罫線・表・寸法線が「読む」仕事に直接対応し、カードを廃止できる。B の黒枠は内容より強く、C の全面暗色は「読む」仕事を暗所に閉じ込める。
2. **固有性**: A は図面枠が汎用だが、暗いステージと確認レールが造形の中心にある。B は最も置換に強く（=弱い）。C は信号色の集中先がステージに限定される。
3. **AA の余裕**: 通常文字の最小は A 5.19:1、B 6.38:1、C 5.53:1（C の無効 5.07:1 を除く）。B が最も余裕があり、A が最も小さい。A を推奨する根拠は余裕の大きさではなく、1・4・5 に置く。
4. **実装コスト**: A は罫線・表・システムフォントのみ。B も同程度だが 2px 枠の反復が多く、C は全トークンを暗色で持つ。
5. **拡張性**: A は明るい作業面を保ったまま、入力モニターだけを暗いステージにできる（DESIGN_TAURI の面の二重性を維持）。C は二面性を捨て、B は暗いステージを黒枠の一部として扱う。

補足:

- **B の注意ラベル**は、空状態の「状態 → 次にすること → 行動」の情報順序の参照にする。色・枠は持ち込まない。
- **C のステージ**は、入力モニター単画面の候補として最も強い。全面暗色を採るのではなく、A のステージ部分の描画密度の参照にする。
- 1 画面で 2 つの言語を混ぜない。混ぜると署名が消え、量産感が戻る。

## 11. 未決事項と実装時の注意

- **フォント**: モックは外部リソース 0 のためシステムスタック。実装は DESIGN_TAURI §5.2 の同梱 Noto Sans JP / Hack に置き換え、1180 幅の折り返しを再確認する。
- **ステージの値**: 形を見せるための表示例。実装では未接続時に数値を出さず、プレースホルダーと「接続すると値が動きます。」に戻す。
- **Y 軸の符号**: 上を正として描いたが、生値の Y が上方向に + か − かは実機未確認（DESIGN_TAURI §5.6.1 / §9）。実装は `Y_SIGN` を実機で確定してから固定する。
- **B の橙**: 橙は面・帯・計測値にだけ使い、文字色には使っていない。紙面との明度差は 4.92:1、ページ地（`#DAD5C6`）上は 3.72:1 なので、ページ余白には橙を置かない。
- **C の暗色**: 全面暗色は現行の不満（暗色が平均的）と衝突する。採用するなら、素材と彫り込みで差を作る根拠を別途レビューする。`color-scheme` と OS のダーク設定の扱いも決める。
- **固定枠**: 1180 × 760 は比較用の固定枠。実装は 900 × 620 と 200% ズームの落とし込みが必要（DESIGN_TAURI §5.4）。
